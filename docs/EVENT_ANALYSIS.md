# イベントからの移動先解析

## 動作

通常リンク・既存の静的URL検出・保存済みの学習結果は従来どおり優先する。それでも移動先がない場合、MAIN worldでイベント処理を読取り解析し、URLを確定できれば既存のバックグラウンドタブ作成処理へ渡す。解析できなければサイト権限の確認、探索クリック、元履歴への復帰、学習結果の保存へ進む。

イベント解析ではサイトのハンドラー、ルーター、取得したJavaScriptを実行しない。`eval`、`Function`によるコード生成、動的import、ページAPIの差替え、新タブ内での操作再実行は使用しない。解析結果を学習テーブルへ保存しない。

## 実装

- `vendor/acorn/acorn.js`: MITのAcorn 8.18.0を同梱。サイトが定義したAMD/CommonJSへ接続しないラッパーを付けた。
- `event-analysis.js`: 構文木を読む限定評価器。文字列・プリミティブ値・テンプレート・URIエンコード・確定した条件・対応したナビゲーション呼出しを扱う。getter・任意のページ関数・プロトタイプ経由の値・不明な条件・必要なnavigation state・未対応の構文は直接開く根拠にしない。
- `event-analysis-main.js`: DOMに対応する現在のReactハンドラーと親コンポーネントを読む。Reactの古いツリーと現在のハンドラーが一致しなければ採用しない。Compilerのキャッシュ書込み式から変数と位置を対応させ、propsと現在の保持値を読む。Rspack/Webpackのモジュール定義とimport/exportを構文から対応させ、純粋なURL生成部分を読む。
- `event-analysis-client.js`: 対象要素・リクエストID・元URLを照合するブリッジ。HTTP(S)、同一origin、既存の認証URL・トークン除外を満たす結果だけ返す。1.5秒で応答しなければ従来処理へ戻す。元ページが変わった場合や操作がキャンセルされた場合は開かない。

変数名、モジュールID、Reactキャッシュの位置、ChatGPTのURLパターンは固定していない。既にページが宣言・読込みした同一originのJavaScriptアセットをキャッシュ優先で読む。ソースは最大64ファイル、1ファイル250万文字、合計2千万文字まで。評価はステップ数・呼出深度・時間で制限する。非表示タブでは事前解析を行わず、DOM更新のたびに同じ解析を繰り返さない。

既知のルーターへURL引数をそのまま渡すReact hookは、ルーターの同一性と関数構文を確認して扱う。未使用のimport呼出しは実行せず、URL計算に使う可変オブジェクトへの影響を否定できなければ採用しない。これはクリック処理全体の意味や副作用を再現する機能ではなく、確定したナビゲーション引数を抽出する機能である。

## 対応範囲と制約

単純なDOM onclick、React props、対応するReact Compilerのキャッシュ、Webpack/Rspackのモジュール定義が主な対象。addEventListenerの非公開リスナー、サーバー応答が必要なID、取得できないclosure、複雑な構文、別originのJSアセット、URL以外の状態が必要な操作などは従来学習へ戻る。すべてのReactアプリや他フレームワークで解析できる保証はない。

MAIN worldから返る値はページ由来の情報として扱う。元タブのクリック・フォーム送信・送信APIの呼出しを解析目的で行わない。既存の探索クリックは従来のサイト権限が必要であり、解析失敗を理由に確認を省略しない。

## 検証

### 自動テスト

`node --test tests/*.test.cjs`は143件すべて成功。既存のリンク・学習・同意・Drive・Codex・タブ配置のテストに加え、次を検証した。

- 変数名・キャッシュ位置・モジュールID・URLパターンが異なるfixtureでの自動対応。
- ハンドラー・getter・文字列化フックを実行しないこと。
- 不明な分岐、必要なstate、可変値、複数の遷移先、不正URLの拒否。
- 古いReactハンドラーと別の祖先コントロールを借用しないこと。
- ブリッジの対象・ID・元URL・origin・認証URL・タイムアウト・incognitoの境界。
- 解析失敗からの従来学習への復帰と、解析中のページ変更によるキャンセル。

### 実画面

専用Chrome 156.0.8078.80 / 9223、1240×1051 CSS px、DPR 1.5。実装をGitルートから読み込み、拡張・ページを再読み込みして確認した。すべて合成中ボタンイベントであり、物理入力の結果とは区別する。

| 対象 | 結果 |
| --- | --- |
| ホームの未学習プロジェクトAの新規会話 | 解析で直接開いた。権限照会・探索クリックなし、学習記録の増加なし |
| 未送信文とスクロール位置がある既存会話から、別の未学習プロジェクトBの新規会話 | 元表示・入力文・選択・スクロール・履歴・フォーカスを維持。グループを継承し右隣の非選択タブ1件 |
| 上部の通常の新しいチャット | 既存の学習結果でホームへ直接開いた。元タブを保持 |
| 最近の項目の新しいチャット | 通常コンテナーをプロジェクトと誤認する既存判定を修正後、上部と同じ既存学習結果を再利用。追加学習なし |
| 別サイトfixtureの単純なonclick | 権限・学習なしで直接開き、元ページのクリック回数0 |
| 解析不能なaddEventListener制御 | 確認の拒否ではクリック0・許可保存なし・タブ増加なし。承認後は通常学習・元URLと履歴キーへ復帰して1タブを開いた。次回はクリック回数が増えず保存済みURLを再利用 |

ChatGPTの解析経路で、元タブの通常クリック・Navigation APIの遷移はともに0。ナビゲーション開始前の状態と表示本文・入力のハッシュが一致した。最初の2試験で中クリックからタブ作成通知まで879 ms / 403 msだった。これは少数例のタブ作成時間であり、移動先の表示完了時間や厳密なベンチマークではない。新タブの初期URL自体が目的地で、元ページを新タブへ読み込んでから切り替える処理はない。

従来動作の確認で、Recentsが`data-sidebar-project-container-id="chats"`を使うことが分かり、これをプロジェクトIDとして扱わないよう修正した。試験で作られた一時的な学習結果のみ除去し、既存の学習結果とサイト権限を保持している。私的本文・プロジェクト名・ID・認証情報・スクリーンショットはリポジトリに保存していない。

対象拡張service workerのwarn/errorは0件。ChatGPTではサイトのStatsigキャッシュ警告と、導入前から観測されていたsandbox内localStorageのSecurityErrorがあった。後者の発生元は未特定で、対象拡張のエラーとは断定していない。物理中クリック、全サイト・全プロジェクト・全ての初期化タイミングは未検証。
